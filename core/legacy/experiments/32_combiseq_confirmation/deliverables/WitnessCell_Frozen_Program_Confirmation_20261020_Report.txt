任务标签：20261020；实际冻结时间采用 UTC，见下文原始记录。

一、结论先行

本轮完成了两项实际工作：保留 v20 的完整预测系统、基准结果与图件，将后续程序预测和固定参考构造纳入 v21；并在另一个原始研究的 Combi-seq 数据上，执行一次先冻结、后处理表达与评分的确认。

确认结果为 NOT_CONFIRMED。374 个不同药物组合上，在完全相同的端点基线上加入冻结的伙伴项 G，全程序误差增加 0.0232823%，去端点误差增加 0.0302401%。其效应接近零，未达到预先规定的至少 2% 实用增益要求。不能将本轮写成新增能力跨来源确认成功，也不能借此把论文的评价提高到 86 分。

与此同时，查询批次不变性、留出标签隔离、独立算术复核与一次完整离线复现均通过。这确认了本轮负结果来自所冻结流程的实际预测结果，未发现足以改变判定的计算错误。数值正确性不等于科学能力得到支持。

二、完整系统应怎样讲扎实

WitnessCell 的技术基础仍然包括完整的组合响应预测系统及其历史基准表现。组合实验能够提供不同类型的信息：进一步估计端点响应的信息，以及对具体伙伴配对有增量的信息。稿件应将这两类作用分别建模、分别验证，再解释何时可以交付额外伙伴预测。

1. 原有预测系统：保留端点响应构造、原有饱和/残差流程、12 个图划分的历史基准与完整消融。历史四数据集 540 个组合×seed 记录、相对 trainMean 的 24.87% WMSE 改善，属于其原定义的评价口径，不能替代新的非靶或程序主终点。

2. 组合数据对端点估计的贡献：端点 incidence 核的转移项满足 Rhat(q) = [B_g + B_h]/2。因此它可以利用组合训练数据改进端点补偿，但该算子本身不表达“与哪个伙伴配对”的自由变化。这个结构事实不能因总体预测成绩较好而忽略，也不否定端点补偿的实际预测价值。

3. 额外伙伴结构的具体实现：RNA 和生长表型的实现分别对应其测量对象、训练结构与评价。它们组成同一研究框架，不能表述成在所有读出上始终使用同一组拟合参数或同一个均值模型。

4. 测量支持、训练组合数量和预测接口：支持与密度分析为适用范围提供实测依据。查询独立的固定参考构造解决了预测随同时提交的其他候选而变化的问题；它是可交付接口的必要改进，但不是新的生物学独立证据。

5. 冻结后检验：本轮把新增能力放入同信息端点基线后进行确认。结果限制了现阶段的推广范围。不能将负结果重命名为“成功拒答”，因为本轮没有预先建立并验证一个会自动判定该数据集应当拒答的选择器。

四、为什么选择这个确认来源

原始来源为 Mathur 等的 Combi-seq，Nature Communications 13, 4450 (2022)，DOI 10.1038/s41467-022-32197-0。使用大规模 K562 药物组合屏幕 GSE174695；GSE174696 为其父系列，二者只计为一个来源。

在本轮可检索的访问记录范围内，未发现此前使用 Combi-seq 的记录。这是有范围的审计结论，不能证明团队历史上任何成员都从未访问。来源选择依据为实验设计与元数据；公开检索摘要可能呈现原研究结果，因此应称本轮模型结果未见，而不是对整个文献盲法。

此前先核对 Joung 的转录因子组合面板，仅处理元数据。该候选有单 TF+GFP 和 TF 双组合，但未找到满足当前差分程序预测要求的独立无干预对照；因此在处理其 RNA 表达前排除。排除证据单独留存，未因模型在该来源上表现差而排除。

Combi-seq 提供已测单药、明确内部 DMSO_DMSO 对照、组合计数和三次实验运行。它适合检验“冻结的学习程序是否在新来源、另一类组合干预上取得增量”，但不能悄悄替代最初希望完成的跨研究遗传双扰动 RNA 确认。

五、队列、数据处理与划分

原发布矩阵：25,912 个基因行，1,263 个条形码样本。使用的是已发布的池化 reads-per-gene 计数，不是逐细胞 UMI；每个样本先按总 reads 归一到 10,000，再作 log1p。未进行由新表达结果选择的 HVG、DE 或程序筛选。

主要分析包括 36 个药物、374 个不同端点的无序药物对。剔除 3 个来源身份未充分区分的额外 _ctrl 样本和 9 个同药双通道条件，共 1,251 个允许样本。保留全部原样本名、通道方向和 run 标记。相反通道方向先等权平均，再将三个 run 等权平均。通道是同时输入的装置通道，不是给药顺序。

原 Methods 规定相同目标 GR35 剂量；两个通道采用不同 stock 倍数用于补偿注入比例。反向通道按相同目标剂量处理有设计依据，但三个重叠药物的精确数值浓度未独立下载核对成功。此项限制保留在来源审计中。

固定程序原有 54 个符号，旧标识映射提供 52 个；新发布矩阵缺 UBE2C，最终使用 51 个。PIMREG/JPT1 在旧映射中缺失，未在看到结果后更新别名。只复用既有基因标识，不复用 Dixit 表达值。

三折按无序组合身份的确定性哈希划分；测试数 125/125/124，训练数 249/249/250。一个组合在全部 run、全部方向的记录一同留出。所有方法均获得允许的单药和对照，因此这是“端点已测、组合未测”的任务；不声称外推到未知药物端点。

测试 incidence rank 为 36；三个测试折的去端点维度为 89/89/88，合计 266。374 个组合不能当作 374 个完全独立的生物学重复；三个计算折也不是三次独立实验。

六、冻结了什么

主要新增能力：在同信息端点基线 B_endpoint 上加入固定参考伙伴项 G，预测预定义 G2M 程序：hhat(q) = B_endpoint(q) + G_fixed_reference(q)。主要对照是完全相同的 B_endpoint。

G 的原核心代码、固定程序、全 RNA 单药响应的对称乘积特征、训练 incidence 残差化和完整端点身份参考集合均保持原实现。固定参考包括 36 个药物的 630 个可能异药对，仅含端点身份，不含它们未测响应。

训练内 alpha 网格为 0、0.02、0.05、0.1、0.2、0.5；伙伴 lambda 网格为 0.1、1、10；端点噪声网格为 0.01、0.03、0.1、0.3、1，OOF 系数 gamma 限定在 [0,1]。图结构内折及所有参数选择规则在新表达处理前冻结。

一个必须明确的实现细节：为了保持上一轮伙伴算法，lambda 仍由“scalar saturation + G”的训练内部全程序 SSE 选择，没有改为根据完整 endpoint + G 重新选参。这是冻结流程的已知特征，本轮没有在负结果后改动它。当前结果确认的是这个具体流程，不是所有可能的程序伙伴算法。

五种同时报告的方法：实测单药加性、scalar saturation、endpoint control、scalar saturation + G、endpoint control + G。

主要继续要求：新增 G 相对同信息 endpoint control 至少改善 2%；条件端点乘子稳定性下界大于零；优于 saturation；去端点收益大于零；至少两个 run 目标正向；查询与隔离审计通过。2% 参考前一轮 2.267% 开发结果确定，是项目实用门槛，不是期刊标准。
