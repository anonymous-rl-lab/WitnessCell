# Experiment 22 v2 — Metric-calibration stress test

**Protocol ID:** `E22-MCS-v2`  
**Status:** `FROZEN_BEFORE_EXPERIMENT22_FORMAL_EXECUTION`  
**Method under test:** frozen WitnessCell v14 mean-response predictor, Gate 18/19 endpoint decisions, and the already frozen Gate 21 accept/abstain rule  
**Primary domain:** scPerturBench genetic-combination track: Norman, Wessels, Schmidt and Replogle_exp6; official seeds 1–3  
**Decision-stress domain:** Gate 21 Norman development panel only  
**Normative metric source:** Miller et al. repository at the immutable commit recorded in `SOURCE_LOCK.json`

## 1. Purpose and claim boundary

This experiment asks three separate questions:

1. **Metric validity:** do fixed positive and negative controls provide usable dynamic range for the candidate metrics on these datasets?
2. **Prediction robustness:** does WitnessCell retain an advantage over reproducible baselines when scored with prespecified signal-sensitive metrics?
3. **Decision robustness:** do the already frozen endpoint and selective-prediction decisions remain useful when their realized errors are graded with the same signal-sensitive loss?

The experiment is a retrospective stress test on previously available public data and predictions. It is not a new biological validation, not a new prospective dataset, and not an independent replication of the original v14 search. It cannot change v14 predictions, Gate 18/19 decisions, the Gate 21 risk score, or the Gate 21 threshold.

The experiment does **not** claim that:

- DRF is a model score or an uncertainty score;
- a continuous DRF value creates a universal pass threshold;
- NIR measures DEG-list overlap;
- exact v14→v13 fallback is biological abstention;
- the four inactive Gate 19 splits predict the dataset mean;
- WitnessCell is the only perturbation method with confidence or abstention machinery;
- unavailable comparator predictions can be reconstructed from published summary scores;
- a Norman-only Gate 21 result establishes cross-dataset selective prediction.

## 4. Prespecified metrics

Let $y_t\in\mathbb R^p$ be the held-out condition centroid for target $t$, $\hat y_t$ a condition-mean prediction, $\mu_{\mathrm{all},s}$ the source-compatible mean profile constructed from the training non-control conditions of split $s$, and $w_t$ the target-specific truth-side gene weights.

### 4.1 Truth-side gene weights

For each eligible target, use the locked source procedure:

1. create the formal technical-duplicate split before any WitnessCell prediction is loaded (§5);
2. use only the first-half cells as the scoring truth half;
3. run Scanpy `rank_genes_groups` with `method='t-test_overestim_var'` and `reference='rest'`, comparing the target condition with the other eligible perturbation conditions in the same dataset/covariate;
4. take the absolute source score for each gene;
5. min–max scale the absolute scores to $[0,1]$;
6. square the scaled values;
7. for duplicate gene identifiers, retain the maximum weight;
8. align to the evaluated gene order and fill absent genes with zero;
9. normalize by the weight sum inside WMSE, exactly as in the locked source.

This is **not** $t^2/\sum t^2$. If `sum(weights)==0`, the operation is non-evaluable; no uniform-weight rescue is allowed. Missing and non-evaluable counts must be reported by dataset and method.

The source-derived weights require either the held-out cell matrix or an independently demonstrated, bitwise-equivalent implementation from `{mean, variance, n}` summaries. Approximate Welch weights may be reported only as a post-reveal sensitivity analysis.

### 4.2 Primary metric P1: weighted mean-squared error (WMSE)

\[
\operatorname{WMSE}_t(\hat y_t,y_t)
=\sum_g \tilde w_{tg}(\hat y_{tg}-y_{tg})^2,
\qquad
\tilde w_{tg}=w_{tg}/\sum_h w_{th}.
\]

Lower is better. This evaluates condition means; it does not convert WitnessCell into a cell-distribution model.

### 4.3 Primary metric P2: weighted delta R² with respect to training perturbations

Define

\[
\Delta_t=y_t-\mu_{\mathrm{all},s},\qquad
\widehat\Delta_t=\hat y_t-\mu_{\mathrm{all},s}.
\]

Compute scikit-learn `r2_score(Delta_t, DeltaHat_t, sample_weight=w_t)` through the locked `r2_score_on_deltas` entry. Higher is better. This is the source metric `weighted_r2_deltapert`; it is not weighted Pearson correlation.

The split-specific $\mu_{\mathrm{all},s}$ must follow the locked source role: average condition centroids over training non-control perturbations, with each condition contributing once. It must not be recomputed from the held-out target pool.

### 4.4 Secondary metric S1: NIR

NIR is the locked source's **Normalized Inverse Rank** score. For all predictions and truths within the same dataset/covariate:

1. compute the full Euclidean distance matrix from predicted condition centroids to true condition centroids;
2. for target $i$, compare the distance to its matched truth with distances to every other eligible truth;
3. score the fraction of strict comparisons for which the matched truth is closer.

NIR is in $[0,1]$, higher is better. It measures perturbation-identity retrieval. It is not a top-K gene-rank score and is not common-DEG recovery.

At the locked commit, NIR is implemented by the metric engine but is absent from that commit's DRF configuration. Therefore NIR is fixed in advance and reported, but it will **not** be labelled “DRF-certified” in the primary analysis. A later upstream NIR–DRF implementation may appear only as sensitivity analysis.

### 4.5 Context metrics

For continuity and contrast, also compute from the same centroids:

- unweighted MSE;
- Pearson correlation of control-subtracted effects;
- unweighted delta R² with respect to $\mu_{\mathrm{all},s}$.

These context metrics cannot rescue either primary endpoint and are not pooled into a new composite score.

## 5. Metric-validity controls and DRF

### 5.1 Candidate-independent controls

Metric validity is calculated before loading WitnessCell or comparator predictions.

For each dataset, cells within every eligible condition are deterministically permuted using NumPy legacy `RandomState(42)`, matching the locked source's `np.random.seed(42)` plus sequential `np.random.permutation` behavior. The first `floor(n/2)` cells form `first_half`; the remainder form `second_half`. Cell order, condition iteration order, software version and the resulting cell-ID lists are hashed.

- **Truth:** first-half condition centroid.
- **Technical duplicate positive control:** second-half condition centroid.
- **Interpolated duplicate positive control:** the locked source interpolation using second-half target-vs-rest Benjamini–Hochberg-adjusted p-values (`pvals_adj_df_dict` in the locked commit), the second-half centroid, and the split-specific training mean. The adjacent unadjusted-p-value line in the upstream script is commented out and is not normative.
- **Mean negative control:** split-specific training-condition mean.
- **Control negative control:** control-cell centroid where the locked source assigns control as the negative comparator for delta-from-perturbation-mean metrics.

The formal positive control must come from the same formal dataset being evaluated. A disjoint engineering dataset may test code but may not supply the formal DRF ceiling.

### 5.2 DRF computation

DRF is a metric diagnostic, not a model score. Use the locked direction-aware arithmetic with `perfect=0` for errors and `perfect=1` for higher-is-better scores, epsilon `1e-6`, and clipping to `[-1,1]`.

For each metric×dataset×condition, report both locked variants that are applicable:

- negative control → technical duplicate;
- negative control → interpolated duplicate.

Aggregate by median and mean within dataset, then report a dataset-equal summary. The full per-condition distribution and valid denominator are mandatory.

**No DRF cutoff is prespecified.** In particular, `0.5` is not a source-defined threshold and must not be used. DRF cannot select which metrics enter §7: WMSE, weighted delta R² and NIR are fixed before Phase M. A value `DRF<=0` is reported as evidence that the positive control did not outperform the negative control for that metric/condition; it does not authorize replacing the metric after reveal.

### 5.3 Witness-blind phase separation

Phase M may read formal cells, split metadata and candidate-independent controls, but the execution environment must deny access to all WitnessCell and comparator prediction files. After Phase M:

1. write per-condition and aggregate DRF tables;
2. write the exact eligible-operation list and gene-order hashes;
3. hash the entire Phase M result directory;
4. close the process;
5. only then open a new Phase P environment that may load candidate predictions.

The metric list, formulas and prediction pass criteria cannot change after Phase M.

### 6.3 Operation completeness

- every one of the 12 official splits contributes at least one evaluable operation;
- at least 90% of the 654 official units are evaluable for WitnessCell and each mandatory baseline;
- each NIR group contains at least two matched operations.

If these completeness conditions fail, numerical results remain reportable but the corresponding confirmatory claim is `NOT_ADJUDICATED`.

## 7. Prediction-robustness analysis

### 7.1 Aggregation

The 12 splits remain the formal structure. For WMSE:

1. average operation-level WMSE within each dataset×seed split;
2. form the WitnessCell/baseline ratio within that split;
3. report all 12 ratios, the dataset-equal geometric mean ratio and the operation-pooled ratio.

For weighted delta R² and NIR:

1. average operation scores within each dataset×seed split;
2. form WitnessCell-minus-baseline differences;
3. report all 12 differences plus dataset-equal and operation-pooled summaries.

Uncertainty uses 20,000 cluster-bootstrap replicates with clusters defined by dataset×condition identity, keeping all available seed appearances of a condition together. Random seed is `20260822`. Percentile 95% intervals are primary. A dataset-leave-one-out table is a fixed sensitivity analysis.

### 7.2 Confirmatory Prediction Verdict PRED

The strongest reproducible baseline is `linearModel`. `PRED=PASS` requires both co-primary conditions on the common evaluable set:

1. WMSE dataset-equal ratio `<1` and its 95% cluster-bootstrap upper bound `<1`;
2. weighted delta R² dataset-equal difference `>0` and its 95% cluster-bootstrap lower bound `>0`.

Because both conditions must pass, no post-hoc choice between them is allowed. NIR is reported without a pass threshold. Comparisons with `trainMean`, `baseControl` and v13 are mandatory support analyses.

If exact linear predictions are unavailable, report `PRED_LINEAR=NOT_ADJUDICATED` and separately apply the same two conditions against `trainMean` and `baseControl`; these may support a narrower “uninformative-baseline robustness” claim but not the linear-baseline claim.

Published-method ranks, when available, are reported separately for WMSE, weighted delta R² and NIR. No new average rank across the three metrics is a confirmatory endpoint.

### 7.3 Prespecified stratification

The primary analysis pools all eligible official operations. The following are secondary diagnostics only:

- Gate 19 active splits (8) versus inactive exact-v13 splits (4);
- seen0/seen1/seen2 support class where defined;
- dataset;
- target effect-strength quartile defined from truth-side weights.

Fallback operations are never removed from the primary analysis. Negative weighted R² on any subgroup is reported, not treated as a reason to change the pool.

## 8. Decision-robustness analysis

### 8.1 Frozen endpoint decisions graded under canonical metrics

The original Gate 18/19 decisions and v14 predictions remain untouched. Grade v14 against v13 with WMSE and weighted delta R² on the same 654-unit pool.

Mandatory integrity checks:

- the four inactive splits are Schmidt seed 3 and Wessels seeds 1–3;
- v14 and v13 prediction arrays are exactly equal in those four splits;
- the active/inactive labels match Gate 19's frozen files;
- no inactive prediction is described as the dataset mean unless its array actually equals that baseline.

Endpoint compatibility is reported in three levels:

- `STRONG`: all exact-fallback checks pass; pooled WMSE ratio v14/v13 is below 1 with bootstrap upper bound below 1; pooled weighted delta R² difference is above 0 with bootstrap lower bound above 0;
- `DIRECTIONAL`: exact-fallback checks pass and both point estimates favor v14, but one or both intervals include the null;
- `FAIL`: an exact-fallback check fails or either pooled point estimate favors v13.

This is a stress classification, not a rewrite of Gate 19's original verdict.

### 8.2 Training-only shadow endpoint gate

A counterfactual shadow analysis tests whether a signal-sensitive score would have produced similar split-level decisions. It must not alter the deployed v14 method.

For each training-single LOO pseudo-target:

1. hold out that single from all fitting and background construction;
2. construct pseudo-target weights from its response versus the remaining eligible training singles using the locked transformation;
3. evaluate the candidate versus its frozen predecessor with training-weighted WMSE and weighted delta R²;
4. reproduce the original one-sided 95% lower-bound machinery and all nesting rules;
5. record the counterfactual decision.

These weights use the pseudo-target outcome inside training cross-validation. They are therefore **training-only and test-blind**, but not “outcome-free.”

Report the 12-split confusion matrix, exact concordance, active-to-inactive flips, inactive-to-active flips and the four fallback decisions. No arbitrary `11/12` concordance threshold is used. The shadow analysis is descriptive and cannot replace §8.1.

### 8.3 Gate 21: exact-threshold selective WMSE stress

Gate 21 is regraded, not recalibrated.

Immutable requirements:

- risk score: unchanged `estimated_witness_risk`;
- threshold: bitwise reuse `0.0923227147328771`;
- selected query IDs: exactly the original Gate 21 accepted set;
- no new isotonic fit, no new quantile and no threshold search;
- original pair-balanced weights, 20,000 pair-cluster bootstrap replicates with seed `20260811`, and 20,000 within-seed random-selection replicates with seed `20260812`.

The only changed quantity is the per-query loss: canonical truth-side WMSE instead of unweighted MSE. Generating this loss requires gene-level predicted and true response vectors plus valid truth-side weights. The existing scalar `estimated_realized_mse` column is insufficient. If these gene-level assets cannot be regenerated and hashed, `GATE21_WMSE=NOT_ADJUDICATED`; no scalar rescaling or top-gene approximation is permitted.

All 213 decision identities remain in the integrity ledger. If a public
cell-level source lacks a target condition and therefore cannot supply a
canonical weight row, the full 213-query verdict is `NOT_ADJUDICATED`. A
complete-case sensitivity may be reported only if fixed before weighted losses
are computed, at least 90% of rows remain, missing identities are listed, and
the accepted/rejected decisions of every retained row are unchanged. Such a
sensitivity cannot be relabelled as the full-panel confirmatory verdict.

`GATE21_WMSE=PASS` requires the five original criteria, with pair-balanced WMSE substituted for MSE:

1. achieved coverage at the original 0.5 threshold is in `[0.35,0.65]`;
2. accepted/all WMSE ratio `<=0.80`;
3. pair-cluster bootstrap 95% upper bound of that ratio `<1`;
4. one-sided random-selection `P<0.05`;
5. accepted WMSE `<` rejected WMSE.

The risk-to-WMSE rank correlation and any monotone mapping are secondary. They cannot change the pass verdict.

### 8.4 Geometry control

Evaluate geometry risk at matched achieved coverage using the same WMSE rows. Report its accepted/all ratio, uncertainty, random-selection control and accepted/rejected separation.

There is no hard requirement that the geometry ratio exceed 1. The valid comparison is whether Witness risk yields lower selective WMSE than geometry at matched coverage and whether geometry independently satisfies all five criteria. This control is secondary and cannot override the primary Gate 21 verdict.

## 10. Outcome taxonomy

The experiment returns separate verdicts rather than one opaque average:

| Verdict | Meaning |
|---|---|
| `SOURCE_PARITY` | locked metric arithmetic and source files reproduced |
| `METRIC_VALIDITY` | continuous DRF/control results; no universal binary threshold |
| `PRED_LINEAR` | two co-primary prediction tests against exact linearModel |
| `PRED_UNINFORMATIVE` | same tests against trainMean/baseControl |
| `ENDPOINT_COMPATIBILITY` | `STRONG`, `DIRECTIONAL` or `FAIL` under v14-v13 canonical grading |
| `GATE21_WMSE` | original accept/abstain set passes or fails the five WMSE criteria |
| `COMPARATOR_SCOPE` | `FULL_POOL`, `AUDITED_SUBSET` or `MANDATORY_BASELINES_ONLY` |

Permitted manuscript interpretations:

- If `PRED_LINEAR=PASS`, prediction advantage survives the locked signal-sensitive metrics against the linear baseline.
- If `GATE21_WMSE=PASS`, the already frozen Gate 21 selection remains useful under target-weighted loss on its Norman panel.
- If prediction passes but Gate 21 fails, do not claim calibration-robust abstention.
- If Gate 21 passes but prediction does not, centre the paper on selective support and narrow the leaderboard claim.
- If either result is not adjudicated because required assets are missing, say so; do not convert missingness into a pass.

Suggested response-letter wording is conditional and may be used only after the corresponding verdicts pass:

> Using metric definitions and candidate-independent dynamic-range controls fixed from the public reference implementation, WitnessCell retained its advantage under WMSE and weighted delta R²; the previously frozen accept/abstain set also stratified target-weighted error without refitting its risk threshold.

Do not use “certified,” “unique,” “invariant,” or “all well-calibrated metrics” unless a separate result directly supports that word.
